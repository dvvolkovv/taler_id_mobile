# Taler ID Mobile — правила для AI-агентов

## ⚠️ Гигиена чекаутов (инцидент 2026-07-19)

Перед ЛЮБОЙ правкой кода или сборкой в ЛЮБОМ клоне этого репо (бот-сервер, мак Александра `~/android-ci/repo`, сборочные серверы):

1. **Синхронизируйся**: `git fetch origin && git checkout <ветка> && git reset --hard origin/<ветка>`.
   - Фиксы и новые фичи — только на свежий `dev`.
   - Релизные сборки — только `main` (aeza prod / talerid) или `dev` (dev-flavor).
2. **Сверь версию перед сборкой**: `grep '^version:' pubspec.yaml` против `curl -s https://id.taler.tirol/app/version` (`android.build`). Если pubspec СТАРШЕ advertised build — чекаут устарел: остановись и синхронизируйся, НЕ собирай.
3. **Ветки `debug/*`** — только для экспериментов. Релизы из них не собирать. Готовый фикс переносится cherry-pick'ом на свежий `dev`.
4. После работы на чужом/сборочном клоне (особенно мак Александра) — вернуть репо на `main` (`git checkout main && git reset --hard origin/main`), чтобы следующая сборка не подхватила debug-состояние.

**Почему:** 2026-07-19 бот сделал фикс в устаревшем чекауте на ветке `debug/*` (база — 3 релиза назад) и собрал из него «релиз» 1.1.0+197 вместо актуального 1.1.18 — сборка со старым кодом откатила бы все свежие фичи.
